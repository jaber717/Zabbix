# Network Availability v1.1 LAB validation

Date: 2026-09-27

## Result

The `availability-v1.1.0` candidate passed authenticated validation on the LAB
Zabbix 7.0.30 / PHP 8.3.19 instance. Production was not accessed.

The installed LAB tree was older than the repository baseline: its manifest
reported 1.0.0 and it had no release marker. The installer migrated its empty
legacy configuration to the external schema-v2 runtime store, preserved that
store across candidate upgrades, and did not restart services.

## Live checks

- Module ID 31 remained enabled and the widget action returned HTTP 200.
- Five monitored Hosts resolved to five Nodes; one was UP and the four known
  mock network objects were DOWN. Four rows appeared in Needs Attention.
- All five initially appeared under Unassigned with Tier unset; the four
  operational incidents displayed conservative `P?` priority.
- Administrator Edit Sites control and native CSRF token were present.
- Quick Assign persisted after a fresh widget request.
- Site rename, Node rename, order, a two-member `ha_pair`, and a hidden Node
  persisted. The hidden DOWN Node remained resolved and counted.
- A missing Tier was rejected without replacing the valid configuration.
- The final LAB runtime configuration was restored to an empty topology at
  revision 8; no production topology was invented or retained.
- The existing API-only `nbzsync` account was denied web login, so it has no
  configuration UI. Server-side writes also require the native
  Administration/General permission and CSRF validation.

## Persistence and deployment

- Reinstall/upgrade preservation and exact-release idempotence passed.
- Rollback leaves the runtime configuration in place.

## Differences and corrections found live

1. A legacy module could not pass a v1.1-only pre-upgrade file check. A bounded
   legacy structure validator now protects the old tree while allowing upgrade.
2. A staged tree inherited `user_tmp_t` after activation. The installer now
   restores `usr_t`, including on exact-release repeat runs, and the verifier
   rejects an incorrect module context.
3. Same-version idempotence did not compare the installed artifact with the
   requested release. It now requires exact release-manifest equality.
4. The configuration controller needed the native JSON layout and disabled
   view response. Authenticated saves now return parseable JSON.

## Visual limitation

Automated browser visual inspection was not executed because the LAB HTTPS
certificate is not trusted by the isolated browser runtime, and no certificate
warning was bypassed. Server-rendered contracts, real authenticated widget
responses, native theme hooks, scoped CSS, container-query breakpoints, and
JavaScript syntax/static behavior were validated. Pixel-level comparison to the
referenced Claude HTML prototype was not possible because that prototype was
not present in the supplied attachments.
