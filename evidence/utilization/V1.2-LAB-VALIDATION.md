# Network Utilization v1.2.0 — capacity correction LAB validation

Validated on 2026-09-27 in LAB only: Zabbix 7.0.30, PHP 8.3.19, RHEL 9.6. No production system was accessed. Network Availability was not modified.

## Capacity and migration

- Physical port speed is informational. Monitored capacity is resolved independently for IN and OUT from either the fresh interface-speed Item or explicit service/circuit bandwidth. P95 percentages, hot/sustained/capacity-risk state and directional remaining capacity use the monitored values.
- Focused analytics fixture: 1 Gbps physical port, 50 Mbps symmetric service, 32 Mbps IN and 45 Mbps OUT yielded 64% IN, 90% OUT, 18 Mbps remaining IN and 5 Mbps remaining OUT. P95 fixtures at 35/42 Mbps yielded 70%/84%. An asymmetric 100 Mbps IN / 50 Mbps OUT fixture at 45 Mbps each yielded 45%/90% and 5 Mbps minimum remaining. Over-capacity remained signed for explicit presentation.
- Config tests confirmed a legacy `capacity_override_bps` migrates to symmetric service capacity, absent override remains auto/interface-speed, asymmetric values persist, invalid service bandwidth is rejected, and runtime persistence/last-known-good behavior remains intact.

## Authenticated LAB run

- Candidate 1.2.0 installed and verified on the LAB VM. Installer preserved runtime configuration; no service restart. Module ID 36 was enabled, frontend rendered HTTP 200, and chart asset order passed.
- Real LAB interface `ZABBIX-01/ens18` has no usable physical-speed Item. Without a service override the resolver produced no utilization percentage; HTML showed `Not configured` and `Capacity required`. Remaining IN/OUT were 49,901,384/49,995,464 bps; errors/discards were zero. The values are time-varying observations, not fixed fixtures.

Four-range chart checks using the live fixture passed: 1h 20/20 IN/OUT points at 120 Kbps axis top, 6h and 24h 96/96 points at 10 Mbps top, 7d 14/14 hourly trend-average points at 800 Kbps top. Service capacity did not change the traffic-based chart scale; Y-axis labels explicitly contain throughput units.
