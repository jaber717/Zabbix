# Network Utilization v1.2.1 — symmetric service-capacity save fix

LAB validation on 2026-09-27, Zabbix 7.0.30 / PHP 8.3.19 / RHEL 9.6. Production was not accessed. The v1.2 capacity model and Network Availability module were not changed.

## Root cause and correction

The v1.2 Edit Links Save handler invoked the capacity validator for every configured Link. An unrelated, untouched `interface_speed` Link with no reported port speed could therefore raise `Port speed is unavailable...` while the operator was saving a valid `service_override` Link. The message did not identify the offending Link. The form now validates capacity on new or capacity-edited Links; an untouched auto-speed Link can remain in its visible configuration-warning state without blocking a service-capacity edit. Capacity rules are source-specific: physical speed is never required for `service_override`.

The UI normalizes a symmetric single bandwidth input to both directions. The PHP repository independently copies IN to OUT before directional validation when `symmetric_service_bandwidth=true`. Asymmetric configuration requires both values. Persisted service capacity reopens as the service source, symmetric selection and a 50 Mbps input. Existing v1.2 config and legacy overrides remain readable.

## Focused A–F regression

| Case | Result |
| --- | --- |

| B: no port speed, asymmetric service 100/50 Mbps | PASS |

| E: symmetric one-input server payload | PASS; PHP normalization copies IN to OUT |
| F: valid service source with unavailable port speed | PASS; no port-speed blocking error or warning acceptance |

The focused UI rules test also confirmed an untouched legacy auto-speed warning Link is skipped by the Save-time form check; a touched auto-speed Link and a new Link are validated. PHP persistence tests confirmed save and reload retain source and both 50 Mbps values.
