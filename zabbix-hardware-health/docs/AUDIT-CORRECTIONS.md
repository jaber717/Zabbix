# Audit corrections (v0.1 -> v0.2)

Defects identified in Codex's LAB discovery (and the weaknesses it implied), each with the fix and the regression test that now pins it. Tests are in `tests/`; the whole suite runs offline against `tests/fakes.py` (an in-memory Zabbix 7.0 JSON-RPC model).

| # | Defect in v0.1 | Fix in v0.2 | Regression test(s) |
|---|---|---|---|
| 1 | IOSv `sensor.fans/psu/temp.walk` raw SNMP walk inputs were counted as one sensor each (`NO_ENABLED_TRIGGERS` understated the absence of any sensor). | Raw inputs are detected structurally (`snmp_oid` `walk[...]`, walk key, master item of dependents, discovery rule) and excluded from every sensor count. They are reported separately as `raw_inputs`. Declaring a raw walk as a sensor is `ITEM_IS_RAW_INPUT`. A dependent item whose master is a walk is a legitimate concrete sensor. | `TestRawInputsAreNotSensors` (4 tests) |
| 2 | `item.get` did not request `lastvalue`, units, value type, preprocessing, OID or value map; `host.get` did not read model identity. | Item evidence record (value, `lastclock` + UTC + age, units, `snmp_oid`, delay, preprocessing, value map, tags, master, error); host inventory fields and identity items (`system.descr`, `system.objectid`, `system.hw.model` ...) captured; interface availability recorded. | `TestEvidenceIsCaptured` |
| 3 | A category was assigned by regex on item/trigger NAME text; a name match was reported as coverage. | Hints only nominate candidates (`CANDIDATE_UNVERIFIED`). Coverage exists only for sensors the approved policy **declares by exact item key**, and requires: concrete item, enabled, supported, collected, fresh, value interpretable through a verified mapping (or valid units for temperature), and an enabled trigger **bound to that item** carrying the dedicated tags. A trigger whose name says "fan" but is bound to another item does not count. | `TestNoKeywordOnlyCoverage` (7 tests) |
| 4 | FortiGate `ha.*` was not recognised; `redundancy` conflated HA state with fan/PSU redundancy. | Separate categories `ha` and `hw_redundancy`; `redundancy` is rejected in policies; HA never satisfies hardware redundancy or the reverse; the trigger's `hardware_component` tag must match the category. | `TestHaIsSeparateFromHardwareRedundancy`, `test_old_redundancy_name_is_rejected...` |
| 5 | No server-side identity validation: the audit trusted the URL and the policy file's `environment`. | Reads the global macro `{$NETOPS.ENVIRONMENT}` from the queried Zabbix and refuses on mismatch **or absence**; separate URL/token per environment, collisions refused; production policy must define `zabbix.url_regex`; Zabbix must be 7.0.x. Checked before any host/item read. | `TestIsolation` incl. CLI tests asserting no `item.get` after a refusal |
| 6 | Vendor status codes were never interpreted (and could have been guessed). | `config/status-semantics.yaml` registry, **shipped empty**. An entry needs `verified: true`, an evidence reference, and the same vendor as the sensor; otherwise `SEMANTICS_UNVERIFIED`. Unmapped value -> `VALUE_UNMAPPED`. A failed/degraded/absent value is reported as `current_state` but never confused with monitoring coverage. | `TestStatusSemanticsAreNeverInvented` (8 tests) |
| 7 | Stale / never-collected / unsupported / unreachable all collapsed into one `STALE_OR_UNSUPPORTED`; a timeout could look like a hardware fault. | Distinct reasons `NEVER_COLLECTED`, `STALE`, `ITEM_UNSUPPORTED`, `ITEM_DISABLED`; when every polling interface is unavailable the sensor is `BLOCKED/HOST_UNREACHABLE` and no hardware state is inferred. | `TestFreshnessAndReachability` |
| 8 | Temperature had no unit or plausibility check. | Policy declares units (and optionally a plausible range); mismatch / non-numeric / implausible are gaps; `C`, `degC`, `Celsius` and the degree sign are normalised. | `TestTemperature` |
| 9 | Triggers were never checked for routability or cross-tagging. | `TRIGGER_NOT_ROUTABLE` (no `netops_hardware=1` + matching `hardware_component`), `TRIGGER_CROSS_TAGGED` (also carries `netops_alert`). | `test_trigger_without_dedicated_tags...`, `test_trigger_tagged_for_both_actions...` |
| 10 | No per-device / per-vendor outcome model; N/A was undefined. | PASS / GAP / BLOCKED / N/A per device and category; N/A only with a model-specific evidence statement in the policy; a family with no device is BLOCKED; hand-written observations can never contain PASS. Generated four-vendor matrix. | `TestMatrix`, `TestPolicyValidation` |
| 11 | Fixture-only tests (stale test with a vacuous assertion; no isolation or raw-walk test). | New suite (96 tests); `ResourceWarning` clean; fake server logs every call so tests assert "read-only" and "no read before refusal". | whole suite |

## Preserved properties
Read-only API allowlist (`apiinfo.version`, `host.get`, `item.get`, `trigger.get`, `usermacro.get`, `action.get`, `usergroup.get`, `mediatype.get`); audit never writes; empty approved inventories stay empty; exit codes 0 / 2 / 3 (all PASS / gaps or blocked / untrustworthy).

# v0.2.1 follow-up (from Codex's independent LAB acceptance of v0.2, evidence 41f12c3)

| # | Finding | Correction | Tests |
|---|---|---|---|
| 12 | `{EVENT.TAGS.hardware_model}` etc. used the unquoted form; Zabbix 7.0 documents double quotes for tag names with non-alphanumeric characters. | All message macros are generated by `tag_macro()`: `{EVENT.TAGS."hardware_model"}` (quote/backslash escaped, control characters refused). `{INVENTORY.MODEL}` was dropped: LAB hosts have empty inventory, so the model comes from the `hardware_model` tag. | `TestMessageMacros` (8) |
| 13 | One combined verdict hid whether a sensor was unreadable or merely untriggered. | Report schema 3 keeps `telemetry_coverage` (readable, fresh, understood), `alert_coverage` (routable trigger on that item) and `notification_readiness` (action exists, enabled, delivery validated) apart, at sensor, category, host and report level. The host `verdict` stays the strict combination. A sensor that reads fine without a trigger is telemetry PASS / alert GAP and keeps its value. Alert coverage is `NOT_EVALUATED` when telemetry fails. Readiness is `NOT_READY` unless an independent validation record exists; it is never derived from coverage. | `TestSeparateDimensions` (7) |
| 14 | The handoff expected `raw_input_count` 3; SITE-A returned 12 (it includes non-environmental raw inputs). | The total is kept; `environmental_raw_input_count` and a per-input `environmental` flag report the fan/PSU/temperature/redundancy/HA subset. The classifier did not recognise `temp` (as in `sensor.temp.walk`); fixed. Expect: total = all raw inputs, environmental = the subset. | `TestRawInputCounts` (2), `test_temp_walk_is_environmental` |
| 15 | Missing item, unreachable host and stale data were not clearly distinguished. | `ITEM_MISSING` = a configuration fact, reported as GAP even if the device is down (the item either exists in Zabbix or it does not). Item exists + every polling interface unavailable = `BLOCKED/HOST_UNREACHABLE`. Item exists + device available or availability unknown + old data = `GAP/STALE`, described as a polling/item problem, "not a hardware fault". Each sensor carries `reachability` (`available`, `unreachable`, `unknown`, `none` for API-only hosts). None of them sets a hardware state. | `TestMissingUnreachableStale` (5) |
| 16 | The shipped example silently pointed at a group that does not exist; a tester substituted Zabbix administrators in a temporary plan. | Recipients are explicit and operator-approved: `usergroups`, `approved_by`, `approval_reference` are mandatory; the shipped example is blank and is refused; an absent group is a conflict and is never replaced by another group; the applied action is shown to carry exactly the approved group ids. | `TestExplicitRecipients` (6) |

Preserved: action disabled by default and enable-gated on independent evidence; strict exclusion between the hardware and Interface Alerting actions (model + live-filter check); LAB-only action management; read-only audit allowlist; empty approved inventories; Interface Alerting v1.0.2 byte-identical.

# v0.2.3 security remediation (from the v0.2.2 rejection, evidence 84d1601)

| # | Reproduced defect | Correction | Regression tests |
|---|---|---|---|
| 17 | Case B/C passed after the action was disabled (history alert + ledger mark were treated as proof). | Negative cases (B, C, D) need bounded, timestamped before/after observations of the exact action id (status, definition hash), `sent` marks and event clocks inside the interval, no disabled observation in between, window check; otherwise INCONCLUSIVE. A zero alert count alone is never a pass. | `TestFix1NegativeCasesNeedEvidence` |
| 18 | `action apply` updated an operator-owned same-name action. | Ownership = local record (id, nonce, hash) + nonce in the live message + unchanged definition; enforced in `plan`, in `apply` at the write (fresh re-read by id), and in `rollback` (exact id from the backup). The synthetic workflow refuses a pre-existing action outright; the acknowledgement key was removed. | `TestFix2PreExistingActionOwnership` |
| 19 | A foreign object in the synthetic namespace left an enabled test action without a disable plan. | `emergency_disable_plan` is independent of fixture cleanup (exact id + ownership evidence only); `cleanup_plan` still blocks every deletion on foreign/mismatched ids and prints the emergency step; unowned actions are never disabled by name; refusal carries manual-recovery evidence (ids/hashes only). | `TestFix3EmergencyDisableIsIndependent`, `TestCombinedSequence` |
